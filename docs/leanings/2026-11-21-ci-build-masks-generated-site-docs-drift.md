# 2026-11-21 — CI's build step masks drift in the generated site docs data

- **Status:** Resolved
- **Task/context:** Closing the open follow-up of [2026-11-21 — Fresh-worktree test suite needs a local build and a numpy interpreter](2026-11-21-fresh-worktree-test-suite-needs-local-build.md): nothing failed when the tracked `packages/site/src/docsData.json` drifted from `packages/coding-agent/docs`.
- **Unexpected observation or failure:** #193 edited `packages/coding-agent/docs/code-indexing.md` without regenerating `docsData.json`. CI stayed green, but every later `npm run build` in a worktree dirtied the tree, and the dirty tree blocked `./reinstall.sh`, which requires a clean checkout.
- **Evidence:**
  - `packages/site` runs `scripts/build-site-docs.js` from both `prebuild` and `build`, so the root `npm run build` rewrites `docsData.json`.
  - `.github/workflows/ci.yml` runs `npm ci --ignore-scripts`, then `npm run build`, then `npm run check`. No step compared build output with git.
  - `node scripts/build-site-docs.js --check` against `origin/main`'s `docsData.json` and the current docs reports exactly `packages/coding-agent/docs/code-indexing.md changed`.
- **Approaches tried:**
  - **Attempt:** Add the drift check to `npm run check` only.
    - **Outcome:** Partial
    - **Why:** Locally it works. In CI, `npm run check` runs after the build has already regenerated the file, so the check compares the file with itself and always passes.
  - **Attempt:** Compare with the git index or `HEAD` instead of the working-tree file.
    - **Outcome:** Did not work (rejected)
    - **Why:** Local `npm run check` runs before committing, so a correctly regenerated but not yet staged file would fail. The check would depend on git state rather than on the files under review.
  - **Attempt:** Keep the check in `npm run check` and also run `npm run check:site-docs` as its own CI step before `npm run build`.
    - **Outcome:** Worked
    - **Why:** The pre-build step sees the committed file; the local gate still catches drift before commit.
- **Root cause:** A tracked file is regenerated by the build, and CI checked the tree only after building, so drift between the generator's inputs and the committed output was invisible.
- **Resolution:** `scripts/build-site-docs.js --check` regenerates the data in memory, names each changed, new or removed doc and any `docs.json` navigation/redirect change, and prints the fix command. It runs as `check:site-docs` in `npm run check` and as a CI step before the build. `AGENTS.md` records the regenerate-and-commit rule.
- **Verification:** `scripts/build-site-docs.test.js` (14 tests, in `test:scripts`) covers name-ordered top-level docs only (subdirectories and directories named `*.md` are skipped), an up-to-date file, a changed doc (and that the suggested regeneration repairs it), a new and a removed doc, `docs.json` changes, formatting-only drift, a missing, corrupt or `files`-less data file, a missing `docs.json`, rejected mistyped flags, and the `package.json`/`ci.yml` wiring including step order. `npm run check` passes on a branch whose data file is current.
- **Prevention/follow-up:** The wiring test fails if the CI step moves after the build or leaves `npm run check`.
- **Reusable learning:** A check that compares a build-generated tracked file with git must run in CI before the build step; after the build it only compares the file with itself.
- **References:** `scripts/build-site-docs.js`, `scripts/build-site-docs.test.js`, `.github/workflows/ci.yml`, PR destinationworks/p#202.
