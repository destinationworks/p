# 2026-10-31 — Pasted path mentions deadlocked STRICT task verification

- **Status:** Resolved
- **Task/context:** A user ran p v5.0.2 in the main checkout and pasted its startup screen to report a skill-frontmatter error. Under STRICT evidence verification, the agent (a local Qwen 27B model) needed one edit to `~/.agents/skills/onepassword-cli/SKILL.md`.
- **Unexpected observation or failure:** Every `edit` and `bash` call, including read-only `git rev-parse` and `sed -n`, plus an undeclared extension tool (`studio_repl_status`), was refused with "More than four distinct critical proof boundaries were discovered, or the authoritative source catalog exceeds its eight-source limit. Ask the user to narrow the authoritative source set before mutation." `record_completion_checklist` was refused with "More than 8 requirement-source candidates were referenced." The agent asked the user twice through `ask_user`. The user confirmed "one file, one requirement" both times, and nothing changed. The session ended `partial` with the one-line fix undone.
- **Evidence:** Session `~/.p/agent/sessions/--Users-dst-dev-p--/2026-10-30T17-25-30-993Z_01a18dd8-…jsonl`. The pasted text named ten document paths, nine of them `~/…/SKILL.md` and `~/.p/agent/AGENTS.md`, and cited none of them as a requirement source. Before the fix, `referencedRequirementCandidates` on that text returned `.p/agent/AGENTS.md`, `dev/p/.p/skills/reddit-publishing/SKILL.md`, and so on, which is ten candidates and therefore overflow.
- **Approaches tried:**
  - **Attempt:** The agent's own workarounds: `declare_task` with `non_runtime_content`, a narrower checklist, and `ask_user` confirmation.
    - **Outcome:** Did not work
    - **Why:** Overflow was computed from every path mention in every task prompt and checked before scope. `ask_user` answers are tool results, not direct prompts. The only working escape was `deauthorized_source_paths`, at three paths per call and only for paths named in the latest direct prompt, and no message mentioned it.
  - **Attempt:** Count only cited sources toward the bound, using a per-candidate `isAuthoritativeRequirementSourceCandidate` filter.
    - **Outcome:** Partial
    - **Why:** The behavior was correct, but each candidate rescanned the whole prompt. A 3,000-path paste took about 12 s per catalog call, and `Map` lookups keyed by long sliced strings were slow in V8. A single-pass citation index with 8-character suffix buckets brought this to tens to hundreds of milliseconds, with identical results.
- **Root cause:** The eight-entry catalog bound was meant to keep cited (authoritative) sources from being silently dropped, but it counted bare mentions too. `~/` paths were not treated as absolute, so home paths became fake workspace candidates. An overflow then blocked the checklist itself, which is the only state that lets potential mutations through, and the recovery instructions were vague. Because read-only discovery outside a narrow allowlist counts as a potential mutation, the block also covered inspection, contradicting `docs/usage.md`.
- **Resolution:** Only cited sources can overflow. Bare mentions fill the remaining catalog slots, and the model may still select any referenced path through `authoritative_source_paths`, with an explicit eight-entry ledger bound. `~/` tokens are not candidates. Overflow messages name the cited paths and the exact recovery (a plain-text user reply, then `deauthorized_source_paths`, or `/verify light`). Narrowing now works with more than eight cited sources: each `deauthorized_source_paths` call (three paths at most) is saved even while the set is still too large, and a source cited beyond a full eight-entry selection ledger blocks instead of vanishing. For the verification gate only, `cd`, standard-stream duplication, `git rev-parse`, `git ls-files`, `git branch` without arguments, and `git -C` read-only forms are classified as read-only; the narrow predicate that decides project-rule tool trust is unchanged.
- **Review findings fixed before commit:** An independent critic found that (a) the reconcile step silently truncated selections to eight once any referenced path could be selected, (b) with twelve or more cited sources the three-per-call deauthorization could never reach eight because overflow was recomputed before persisting, (c) the audit engine was told to use evidence-engine tools, (d) the batch citation index diverged on case-colliding paths and case-folded extensions and was quadratic for short paths, and (e) widening the shared read-only predicate also widened the project-rule trust boundary. Each has a regression in `task-requirement-source-overflow-recovery.test.ts` or `task-verification-read-only-shell-discovery.test.ts`.
- **Verification:** Regression `packages/coding-agent/test/task-verification-pasted-path-mention-overflow.test.ts` replays the pasted screen and failed before the fix. Also covered by `task-requirement-source-candidate-catalog.test.ts` (including equivalence between the batch index and the per-candidate check) and `task-verification-read-only-shell-discovery.test.ts`. The existing overflow, lifecycle, compaction, and audit-mode suites pass.
- **Prevention/follow-up:** Any fail-closed bound must name the exact recovery action in its message, and a recovery path must exist that the blocked state itself does not block. Possible follow-up: let an `ask_user` answer that names paths count as narrowing authority.
- **Reusable learning:** A safety bound must count only the inputs it protects. Here those are explicit citations, not every token that looks like a path. A block the agent cannot clear, with a message that does not say how to clear it, turns a guard into a session killer.
